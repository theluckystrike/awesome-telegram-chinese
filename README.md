# Telegram 官方搜索，对中文有多不友好
---

先做个实验，你现在就能打开 Telegram 跟着做。

搜 `web dev`。

再搜 `前端开发`。

两件事是一件事，两个词是一个词。但你会发现，前者的结果基本可用，后者的结果基本是噪声。

这不是你的问题。也不是中文内容少的问题。

是**这条搜索链路，在设计上就没为中文准备过**。

下面是我在找中文频道时，一点一点拆出来的几道坎。

### 一、username 根本不支持中文

Telegram 的用户名规则是公开的：只允许 `a-z`、`0-9`、下划线，5 到 32 个字符。

也就是说，一个中文频道无论叫什么名字，它的 `@username` 只能是拼音、英文或者一串没意义的缩写。

于是这里出现了一个分裂：

- **名字**（title）可以是中文 —— 「前端开发圈」
- **地址**（username）只能是拉丁字符 —— `@frontend_dev_cn` 或者 `@qdkf2023`

你搜「前端」，搜的是名字。

但 Telegram 的全局搜索对 username 的匹配权重明显更高 —— 因为那是唯一稳定、唯一可枚举、唯一不会重复的标识。

结果就是：**你用中文搜，系统最擅长匹配的那个字段，压根没有中文。**

英文频道没这个问题。`web dev` 既是名字也是地址，两个字段说的是同一件事。

中文频道的名字和地址是脱节的，而搜索主要认后者。

### 二、中文没有空格，分词直接失效

英文天然带分隔符，`web dev` 一看就是两个词。

中文不是。「前端开发」在分词器眼里可能是：

- 一个整体：前端开发
- 两个词：前端 / 开发
- 或者被切成别的组合

而中文又**没有词形变化** —— 英文里 `develop`、`developer`、`developing` 共享词干，能靠 stemming 归一到一处。中文没有这个机制。

「前端」「前端开发」「前端er」「前端开发圈」「前端日报」，在系统看来是五个互不相干的字符串。

于是搜索退化成了最笨的字符串包含匹配：你输入的字，必须原样出现在频道名里。

稍微换个说法，就断了。

你以为你在做语义检索，其实你在做 `indexOf`。

### 三、全局搜索排在最末位，藏得很深

Telegram 的搜索有个明确的优先级：

```
你的联系人 → 你加入的群 → 你的聊天记录 → 全局公开结果
```

前三类是本地数据，快，所以排在前面。

公开的频道和群组，要滚到底或者点进专门的全局搜索入口才看得到。

「找一个新频道」这件事，用的恰恰是优先级最低、藏得最深的那一层。

它是**找已知**的工具 —— 找你聊过的人、找你发过的消息、找你已经加过的群。

而"发现一个我不知道存不存在的频道"，本质上是**找未知**。

这条路官方就没打算给。

### 四、排序看热度，不看相关度

就算你翻到了全局结果，还有一道坎。

从现象上看，Telegram 全局搜索的排序主要依据**成员数和热度**，而不是关键词相关度。官方从来没公布过这套算法。

这带来一个结果：**大频道永远在前面，小频道永远沉底。**

一个三千人的水群，排在两百人的优质技术频道前面。

因为前者的热度高，跟它跟你搜的词有多大关系，没关系。

对英文圈来说这个问题也被吐槽，但至少关键词匹配还能用，噪声少一点。

中文这边是双杀：分词先失效一轮，热度排序再把剩下那点相关性冲掉。

你搜「前端」，出来的是成员数最多的那几个带「前端」字样的东西 —— 大概率是卖课的。

### 五、没有分类，搜索是唯一入口

最后一道，也是最根本的一道。

Telegram 官方**没有频道目录**。

没有类目树，没有标签，没有「科技 / 开发 / 前端」这种你能在 App Store 里随手点的东西。

频道叫什么、算哪个领域，全凭创建者心情。

所以「浏览」这个动作在 Telegram 上是不存在的，你唯一能做的是「搜索」。

而前面四道坎已经证明了：中文的搜索，是坏的。

于是发现渠道退化成了最原始的形式 —— **人传人**。

有人在群里丢个链接，你点进去，哦，还有这么个频道。

效率取决于你的人脉，不取决于内容质量。

---

### 所以指望不上的时候，大家在用别的办法

官方这条路堵死后，中文用户实际上在用这几招，各有各的毛病：

**Google `site:t.me`。** 能搜出一些，但排前面的是 SEO 做得好的，不是内容做得好的。内容质量不参与排序，链接的"存在感"才参与。而且不少点进去已经失效，或者频道早改行了。

**收藏夹里的导航文章。** 「100 个必关注的 Telegram 频道」这种。问题不是写得不好，是它是一张**快照** —— 频道会关、会改名、会转型，文章不会更新。半年过去，一半失效。

**TGStat 那类英文数据站。** 数据是全的，但界面是英文，中文频道收录稀疏，核心功能在付费墙后面。它能告诉你一个频道的订阅数曲线，但没法告诉你"中文圈里有哪些值得一读的技术频道"。覆盖面和语言，两头都不靠。

这几招解决的都是局部问题。**没有一招能替代"一个中文的、能按类目浏览的分类索引"。**

后来我找到了：[电报导航](https://tgindex.org)。

### 它在做的事

**先把三类实体分开。**

频道、群组、机器人各有独立入口：

- 频道 — https://tgindex.org/channel/
- 群组 — https://tgindex.org/group/
- 机器人 — https://tgindex.org/robot/

很多目录站是把三者混在一起的，你搜个关键词出来一堆机器人，找频道还得自己筛一遍。

**再建分类。**

20 多个类目：资讯新闻、影音资源、资源分享、软件综合、知识学习、iOS 资源、兴趣社群……

你可以不搜索，直接按类目往下翻。

这一点其实是在补官方最缺的那块 —— **浏览**。

对"我也不知道要找什么，就是想看看有什么"这种场景，比搜索有用得多。

**搜索免登录。**

```
https://tgindex.org/search?q=关键词
```

打开就能搜，不用注册，没有付费墙。而且它是面向中文内容建的，不用跟英文内容抢排序。

**收录是开放的。**

发现好频道可以自己提交（https://tgindex.org/submit），觉得某条收录有问题也能举报。

散落的东西之所以散落，就是因为没人持续捡。开放提交至少让这件事能转起来。

**还有个细节：它自己能被索引。**

页面带 Schema.org 结构化数据，`sitemap.xml` 也是通的。

一个做索引的站，自己都不被索引就搞笑了 —— 这点它没翻车。

### 也说说局限

- **规模还不算大。** 各分类加起来一千多条，跟百万级的数据站没法比。它聚焦中文，取舍就在这。
- **质量依赖社区。** 开放提交意味着良莠不齐，能举报，但处理速度取决于维护者。
- **首页推荐位的筛选还不够严。** 我翻的时候看到过几条明显不该出现的收录混在里面，加一层过滤会好很多。

### 最后

回到标题那个问题：Telegram 官方搜索，对中文有多不友好。

我的判断是 —— **它不是坏了，它只是没为中文设计过。**

username 不支持中文、分词假设有空格、全局搜索藏在最末、排序看热度不看相关度、官方压根没有目录。

五件事单独看都是产品取舍，叠在一起，就是中文内容在 Telegram 上**系统性不可见**。

内容是真的有的。中文 Telegram 圈的活跃度一点不低，技术、资讯、影音、资源，什么都有。

只是官方那条路走不通而已。

所以换个地方找：

https://tgindex.org

不用注册，打开就能搜。

要是你在上面发现了什么好频道，记得顺手提交一下。

散落的东西，得靠一个个捡回来。
